# KrasPro LLC

Сайт компании по наружному ремонту домов в Мэриленде. Next.js строит страницы заранее из данных проекта. Для приёма заявок через `/api/quote` требуется сервер Node.js.

## Запуск

Используйте Node.js 20, как в GitHub Actions, или Node.js 24 для разработки. Сборке нужен доступ к Google Fonts для загрузки Playfair Display и Source Sans 3.

```sh
npm ci --legacy-peer-deps
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Перед публикацией выполните проверки и запустите собранный сайт.

```sh
npm run lint
npm run typecheck
npm run build
npm run start
```

Если сервер разработки запущен в той же папке, остановите его перед сборкой. Обе команды Next.js пишут в `.next`.

## Переменные окружения

Для локального запуска задавайте переменные в `.env.local`. На хостинге задайте их в настройках окружения до сборки.

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Подтверждённый публичный адрес сайта с протоколом, без пути. Используется для canonical, Open Graph, JSON-LD, `/sitemap.xml` и ссылки в `/robots.txt`. |
| `RESEND_API_KEY`, `SMTP_HOST` | Имена переменных для будущей интеграции с почтой. Пока обработчик не подключён, оставьте их пустыми для локальных проб. |

Если `NEXT_PUBLIC_SITE_URL` отсутствует, проект использует подтверждённое значение `site.siteUrl` из `data/site.ts`. Если оба значения отсутствуют или некорректны, карта сайта пуста, а в robots.txt отсутствует ссылка на карту. После настройки адреса пересоберите сайт и проверьте оба файла на публичном домене. Значения `lastmod` берутся из дат изменения исходников страницы и её данных.

Обработчик формы проверяет данные и согласие, принимает необязательное изображение до 1 МБ и ограничивает частоту запросов в памяти каждого экземпляра сервера. В режиме разработки без параметров почтового провайдера он возвращает сообщение о пробной отправке и пишет содержимое заявки, включая вложение, в серверный журнал. Используйте этот режим только с вымышленными данными. В опубликованной версии форма возвращает `503` для корректной заявки и не записывает её содержимое в журнал. Для приёма заявок подключите отправку в `app/api/quote/route.ts` и проверьте доставку. Храните секреты только в серверном окружении.

## Деплой на Cloudflare Workers

Workflow [deploy.yml](.github/workflows/deploy.yml) запускается при push в `main`. Он устанавливает зависимости на Node.js 20, собирает и публикует Worker через OpenNext, проверяет HTTP 200 на главной и пишет её адрес в итог запуска. Страницы, подготовленные при сборке, хранятся в статических ресурсах Worker.

Проект закреплён на Next.js 14.2.35. OpenNext 1.15.1 и Wrangler 4.86.0 выбраны для совместимости с этой версией Next.js и Node.js 20. Для установки по lock-файлу workflow использует `npm ci --legacy-peer-deps`.

1. В Cloudflare включите поддомен `workers.dev` и создайте токен для деплоя Workers с правом `Workers Scripts Write` для нужного аккаунта. [Документация Cloudflare](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/#authentication)
2. В репозитории GitHub откройте **Settings → Secrets and variables → Actions → New repository secret**. Добавьте `CLOUDFLARE_API_TOKEN` с токеном и `CLOUDFLARE_ACCOUNT_ID` с идентификатором того же аккаунта. Установка этих секретов не требует запуска `wrangler login`.
3. После push откройте **Actions → Deploy to Cloudflare Workers**. Если секреты добавили позже, повторно запустите workflow из вкладки Actions для `main`.

Workflow получает публичный адрес из поддомена аккаунта и имени Worker в `wrangler.jsonc`. Если к Worker уже подключён другой домен, задайте его через переменную Actions `NEXT_PUBLIC_SITE_URL`. Проверка после деплоя обращается к адресу `workers.dev`.

Для локальной проверки сборки в среде Workers выполните команды из корня проекта. OpenNext рекомендует Linux или WSL для сборки на Windows. [Документация OpenNext](https://opennext.js.org/cloudflare/get-started)

```sh
npm ci --legacy-peer-deps
npx @opennextjs/cloudflare build
npx @opennextjs/cloudflare preview
```

## Услуги, проекты и отзывы

- **Услуги.** Добавьте или обновите запись в массиве `services` в `data/services.ts`. Укажите уникальный `slug` строчными буквами через дефис, название для меню, заголовок страницы, уникальные `metaTitle` и `metaDescription`, вводный текст, преимущества, 3–4 этапа, минимум 4 ответа FAQ, связанные услуги по их `slug` и изображение. Страница, меню, список услуг, форма и карта сайта используют этот массив. После изменения пересоберите сайт.
- **Изображения.** Храните фото услуг в `public/images/services`, а фото выполненных проектов в `public/images/projects`. Указывайте в данных путь от `/images/` и содержательный `alt`. Для галереи используйте `data/projects.ts`. После замены демонстрационной картинки поставьте `isPlaceholder: false` или уберите необязательный флаг у изображения услуги.
- **Отзывы.** Добавляйте в `data/reviews.ts` только проверенные отзывы, которые можно публиковать. Для каждой записи укажите имя, дату в формате `YYYY-MM-DD`, `slug` услуги, оценку от 1 до 5 и исходный текст. Пустой массив показывает сообщение о том, что отзывы ещё появятся.

## Assumptions

- В названиях услуг исправлены `Bourns` → `Barns`, `Winil` → `Vinyl`, `Lid paint` → `Lead paint` и `Door and Windows` → `Door and Window`.
- `Rain Cap Installation` означает установку защитного колпака на дымоход.
- `Exterior Capping` означает облицовку наружной деревянной отделки гнутым алюминием из рулона, также известную как `trim coil wrap`.

## Перед публикацией

Запустите `npm run check:placeholders`. Команда выводит список заявлений для подтверждения, полей владельца и картинок к замене с указанием файла и строки. Она также запускается автоматически перед сборкой. Найденные заглушки выводятся как предупреждения.

- [ ] Замените каждое значение с префиксом `TODO_OWNER:` в `data/site.ts` подтверждёнными данными. Укажите телефон в международном формате, email, адрес, ZIP, часы работы, номер MHIC, время ответа, ссылку на отзывы, историю компании и публичный адрес сайта. Если необязательного сертификата EPA или ссылки на отзывы нет, оставьте соответствующее поле пустым.
- [ ] Подтвердите территорию действия лицензии и страхование, продажи без комиссии, предоставление фото до сметы, детализацию сметы и уборку после работ. Обновите `site.trust` и проверьте публичные формулировки при изменении этих условий.
- [ ] Подтвердите зоны обслуживания. В плоском массиве `site.serviceAreas` перечисляйте города сразу после их округа. Baltimore City указывается отдельно.
- [ ] Подтвердите партнёра, условия и раскрытие сведений о финансировании до добавления конкретного предложения.
- [ ] Замените помеченные картинки главной, услуг и галереи, затем проверьте подписи и альтернативный текст.
- [ ] Утвердите текст политики конфиденциальности, настройте доставку заявок и проверьте обращение с данными и вложениями.
- [ ] Проверьте canonical, robots.txt и карту сайта на подтверждённом домене. Повторите сборку и проверку заглушек.
